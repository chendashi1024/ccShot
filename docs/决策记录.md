# CcShot · 决策记录

> 记录已经拍板的决定，以及当时的理由。新的决定往下追加，写上日期。

## 2026-11-03

| # | 决定 | 理由 / 说明 |
|---|---|---|
| 1 | **目标：拿 GitHub star，作为简历背书** | 项目会放在个人网站上展示。要求解决真实痛点、真能跑的代码（不是 awesome 清单或文档）、小工具也行、容易看懂。 |
| 2 | **方向：开源 Mac 截图标注工具** | 作者自己在用 Snipaste，有切身痛点：截图里的字不好复制、想截完直接问 AI。 |
| 3 | **MVP 要轻** | 不做大而全，但基础截图标注功能必须有。第一版 3 周做完。录屏、长截图、历史、本地模型、Windows 等放以后。 |
| 4 | **核心卖点：截完直接选字 + 一键问 AI** | 选字像微信截图 / Live Text，本地识别；问 AI 一个键。 |
| 5 | **AI 用 BYOK（用户自带 Key）** | 我们不提供模型、不部署模型。默认 DeepSeek（便宜）；预设 GPT、Claude、Gemini、通义千问、Kimi、智谱、OpenRouter 等主流厂商；也能自定义 Base URL + Key + 模型名。参考 CC Switch 思路，但做简单：所有 AI 设置在一个设置页。Key 存 macOS 钥匙串。 |
| 6 | **不买苹果开发者账号，不签名公证** | 作者原话：「因为我们本来做的就是开源的，我们在自己做这个不太合适」。只做 ad-hoc 签名，在 GitHub Releases 发 .dmg / .zip，README 写清首次打开方法；可选自建 Homebrew tap；以后有赞助再考虑签名。 |
| 7 | **F1 一键唤起截图，照搬 Snipaste** | Snipaste 最好用的一点。Mac 上 F1 默认是调亮度，需要 Fn+F1 或打开「标准功能键」；另提供一个备选组合键（具体哪个待定）。 |
| 8 | **标注样式要好找** | 解决 Snipaste 粗细、样式难找的问题：选中工具或对象，样式调节条立刻在工具栏下方展开；滚轮或 `[` `]` 调粗细；每个工具记住上次样式。 |
| 9 | **加入截图美化（基础版进 MVP）** | 截完加背景，自动输出 1920×1080 等尺寸，可选渐变 / 纯色背景（自选图片背景是 P1），参照 OpenScreen 的画面合成面板。竞品调研发现开源同类几乎都有，所以它是标配、不是卖点。 |
| 10 | **产品名：CcShot** | cc 是作者名字缩写，可当个人品牌。大小写固定为 **CcShot**（文件夹、文档、GitHub 仓库统一）。ShotLens、AskShot、ShotAsk、SnapLens 都有撞名。ccshot.app / .dev / .io 未注册，ccshot.com 已被挂牌出售。 |
| 11 | **项目文件夹** | 初期在 OPC 仓库内。2026-11-08 迁至同级目录 `~/Documents/ccShort`，独立仓库为 [ccShort](https://github.com/chendashi1024/ccShort)。 |
| 12 | **UI 是产品重点，参考成熟付费软件复刻体验** | 用户强调 UI 的重要性，并要求参考付费软件。UI 与功能并列验收；主代理本轮按已有参考对象以 CleanShot X 为主制作[第二版试稿](UI参考与设计.md)，具体画面仍待用户审阅，不作为原生实现完成或最终设计批准。 |
| 13 | **常用工具首排直达，相关参数随选中自动出现** | 用户要求核心功能好懂、不得过度简化，随后认可整体风格并要求点箭头等工具即在对应下方显示参数，不得多点一次样式。线型和类似几何属性用图形预览；字号和主要操作保留数字/中文。常用按钮稳定、图标文字整体居中；AI/美化后续再排，完整原生验收仍按实际证据。 |
| 14 | **后续Windows优先本地PaddleOCR模型 + ONNX Runtime** | 用户原话：“那你把这个方案写到项目上去吧，然后我们后续 Windows版本就用这套方案。”RapidOCR可用于验证；接受安装包适度增大以优先识别效果，基础OCR不强依赖GPU、云或API Key。具体模型版本、体积、准确率、速度和逐字坐标待同图实测。Mac当前Apple OCR路线保持不变；Windows尚未开发，验收见[WIN-01–WIN-07](功能清单与验收标准.md#windows-validation)。 |
