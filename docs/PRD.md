# ccShot · MVP 产品需求文档（PRD）

### 2026-11-09 · 基础标注交互修正

以下为当前原生实现规则，覆盖早期对同一操作的描述；依据用户本轮撤销失效与框内拖动误绘制反馈落实。

- ⌘Z 撤销、⌘⇧Z 重做，兼容 Ctrl+Z、Ctrl+Shift+Z、Ctrl+Y。文字输入内只撤销文字；中文候选未确认时不修改画布。拖动中撤销先取消当前操作。
- 画框后可从框内部移动；同类绘图工具下可直接选中旧对象。选择工具可以选各类标注；未选中空心框内部的原图文字仍优先交给选字。
- 画完箭头直接显示两个端点和中间弯曲控制点，拖线身整体移动。空白继续画，Option 拖动可在已有同类对象上新画；切换另一工具后可在框内正常绘制。
- 修改颜色或直线/曲线：选中时只改该对象，未选中时只影响下一次绘制。不能暗中修改上一条。
- Delete 删除选中对象，方向键移动 1 像素、Shift+方向键移动 10 像素；Shift 拖动沿主轴移动，Shift 绘制矩形/椭圆为正方形/正圆。
- 一次拖动只产生一步历史；单击选中不增加历史。撤销后新编辑清空重做；钉图查看态不改标注。

## 1. 一句话定位与目标用户

**一句话**：像 Snipaste 一样快和轻的 Mac 截图工具，截完文字直接能选，一键问你自己的 AI（默认 DeepSeek）。开源、免费、原生。

| 项目 | 内容 |
|---|---|
| 产品名 | **ccShot**（已定，作者名字缩写 cc + Shot；大小写固定为 ccShot） |
| 目标用户 | 用 Mac 的中文用户：程序员、学生、做内容的人；现在用 Snipaste、系统截图或微信截图 |
| 要解决的痛点 | 截图里的字复制不出来；Snipaste 免费版没有 OCR；标注的粗细、样式藏得深；截完想问 AI 要来回切 App |
| 成功标准 | 从按下快捷键到复制出文字不超过 3 步；从截图到 AI 回答只需一个键 |

## 4. 核心流程

```
按 F1 → 框选 / 点窗口 / ⌘A 全屏 → 编辑态：想做什么？
                                     ├─ 标注（选工具，调节条就在旁边）
                                     ├─ 选字（选择工具下拖选文字）
                                     ├─ 问 AI（⌘J，侧边面板回答）
                                     └─ 美化（B，加背景、定比例）
                                            ↓
                                  复制 / 保存 / 钉图
```

1. **唤起**：按 F1，屏幕变暗，出现放大镜；鼠标下的窗口自动高亮。
2. **选区**：拖拽框选、单击选窗口，或按 ⌘A 选全屏；松手后可拖控制点或用方向键微调。
3. **后台识别**：选区一确定就在本地跑 OCR，用户无感知；识别好之后，鼠标移到文字上会变成文字光标。
4. **选字和标注怎么分开**：默认是选择工具：在文字上拖动就是选字，在别处拖动是移动选区，点已画的对象就是选中它。按下任何标注工具就进入画画；按 V 或 Esc 回到选择工具。
5. **问 AI**：按 ⌘J 或点工具栏「问 AI」，选区旁弹出面板，可点快捷问题或自己输入，回答一个字一个字流式显示。
6. **美化（可选）**：按 B 或点「美化」，截图连同标注一起放进背景画布，按上次预设直接出效果；右侧面板可换背景、比例，调阴影、圆角、内边距。
7. **输出**：回车、空格、点「完成」或用选择工具双击截图内的空白处，复制当前选中的文字或图片并退出。⌘C 复制并保留编辑窗，⌘S 保存文件，F3 钉图。钉住的图上照样能选字、问 AI，按空格还能继续标注。

### F1 在 Mac 上的坑（重要）

Mac 键盘上的 F1 默认是「调暗屏幕」，App 收不到 F1。用户需要二选一：

- 按 **Fn + F1**；或
- 到「系统设置 → 键盘 → 键盘快捷键 → 功能键」打开「将 F1、F2 等键用作标准功能键」。

首次启动时要用一页引导讲清楚，并提供一个**组合键作为备选默认键**（具体用哪个组合键待定，开发时实测避开系统截图键和微信等常用 App 的截图键）。

其他规则：

- 所有全局快捷键都能在设置页自定义，录键控件可以用开源库 KeyboardShortcuts（待验证）。
- 注册快捷键失败（被其他 App 占用）时，在设置页标红，提示用户换一个。
- 截图模式里的单键（R、A、T 等）只在截图模式内生效，不影响其他 App。

## 6. 标注工具栏交互设计（常用功能首排直达）

2026-11-03 用户纠正：箭头、画框、文字等是最重要的常用功能，应在截图后的第一排直接可用，可以一行放得更多；不能为了极简增加操作层级。第三版已据此修订，具体视觉仍待审阅。

```text
[箭头] [画框] [文字] [画笔] [遮挡] [高亮] [序号] | [选择] [撤销] [重做] | [钉住] [保存] [复制] [关闭]
```

1. 截完即可点击常用工具，不设「标注」总入口，也不要求先点「完成」再输出。标注、选字和输出保持同一条工具栏；选字时「复制」变为「复制文字」。
2. 主要标注配图标和中文名称，箭头、画框、文字放最前面；选择、撤销重做等通用图标配提示与可访问名称。只用少量分隔区分操作，不靠缩字号塞满。
3. 点中工具后，在该工具下方自动显示相关参数，无须再点「样式」。箭头显示颜色、粗细、线型与头部；画框显示线型/填充，文字显示字号/加粗/底色。点回选择时收起无关参数，各工具记住自身样式。
4. 截图默认直接选字；选绘图工具才进入对应绘制状态，选择工具或 Esc 返回选择状态。选中对象可继续调整，撤销重做同时保留标准快捷键。
5. 工具栏贴近选区并保持在屏内；小屏和贴边要实际验收，不能让常用工具掉进不可见区域。
6. 设置仍保持快捷键、保存位置两项；AI、美化和高级参数后续再排。权限、Fn 行为、快捷键冲突与保存失败等必要信息就近保留。
7. 用户已认可暖白、深青绿与当前整体风格。线型、粗细、箭头头部和填充用实际图形预览；字号保留数字，主要操作保留图标加中文。图形选项有中文提示和可访问名称；复制文字变宽时，仅扩展按钮末端，不移动已有工具。

## 7. 问 AI 设计（BYOK：用户自带 Key）

原则：**我们不提供模型、不部署模型、不中转**。用户填自己的 API Key，请求直接从用户电脑发到用户选的厂商。默认 DeepSeek（便宜）；预设几家主流厂商；也能自定义 Base URL + Key + 模型名。参考 CC Switch 的思路，但做得简单：**所有 AI 设置都在一个设置页里**。

### 设置页字段（单页）

### 提问面板

- 发送内容：截图（长边过大时先压缩）加本地识别出的文字。

### 不支持图片时只发文字

选了不支持图片的模型（比如 DeepSeek 的 `deepseek-v4-pro`），就只发本地识别出的文字，面板上标一句「这个模型看不了图，已发送识别出的文字」。如果接口报错说不支持图片，自动改成只发文字重试一次，并把这个模型记成纯文字模型。

DeepSeek 旧模型名 `deepseek-chat` 和 `deepseek-reasoner` 已在 2026-07-24 下线，不要预填。`deepseek-flash` 支持图片（原稿依据 DeepSeek 官方图片输入文档，写代码前再核对一次，待验证）。

## 8. 截图美化

- **定位**：竞品基本都有，是标配，不是卖点；在演示 GIF 里当配套功能展示即可。参照 OpenScreen 的画面合成面板。
- **入口**：截图工具栏点「美化」或按 `B`。
- **MVP（P0）**：截图连同标注放到背景画布中间，自动输出目标尺寸；8 到 12 款内置渐变 + 纯色取色；画布比例 16:9（默认 1920×1080）、4:3、1:1、9:16、自由（跟随截图加内边距）；阴影、圆角、内边距三个滑块实时预览；记住上次预设，下次一键出图；复制、保存、钉图都输出美化后的图。
- **P1**：用户自选本地图片当背景，可加模糊（第 3 周做不完就顺延 2 到 3 天或放 1.1）。

## 9. 权限引导

1. **首次启动欢迎页**：一句话说清楚：截图需要「屏幕录制」权限，图片只在本机处理，只有你主动问 AI 时才发给你选的厂商。
2. **一键打开系统设置**：按钮直接跳到「隐私与安全性 → 屏幕录制」；授权后检测到就打勾，提示可能需要重启 App。
3. **选快捷键**：让用户选 F1（附开启标准功能键的图文步骤）或备选组合键。
4. **AI 可以跳过**：不填 Key 也能正常截图、选字，第一次问 AI 时再引导。

补充：

- 第一版只要屏幕录制权限；窗口识别用 ScreenCaptureKit 的窗口列表，不申请辅助功能权限。
- ad-hoc 签名每次升级后签名都会变，系统可能要求重新授权屏幕录制：启动时检测权限是否还在，失效就自动弹出引导页（先在列表里删掉旧条目再重新打开开关），发版说明里也要写清楚。
- 首次打开会被系统拦下（未签名公证），欢迎页和 README 都放图解：系统设置 → 隐私与安全性 → 仍要打开，或用 `xattr -dr com.apple.quarantine` 命令。

## 17. 后续 Windows 路线（2026-11-03新增决定）

后续Windows版优先使用本地PaddleOCR模型 + ONNX Runtime，RapidOCR可用于验证。用户接受安装包适度增大以优先识别效果；基础识字不强依赖GPU、云或API Key，需要可用CPU路径。该决定不替换当前Mac的Apple OCR路线，不改变当前核心版本范围，也不向原44项需求台账添加Windows。

具体模型/权重及运行库版本、模型与完整包体、准确率、速度、逐字坐标和选择效果均待同图实测；本次仅记录方案，Windows尚未开发。验收至少覆盖中文、中英混排、小字、逐字选取、常见CPU性能、多屏DPI及代码/模型/依赖许可，详见[Windows验收清单](功能清单与验收标准.md#windows-validation)与[目标文件](../GOALS.md#windows-roadmap)。Mac原性能目标不自动成为Windows预算，具体阈值在有证据后确定。

## 18. 审美与识字核心方向（2026-11-08）

用户确认先制作框选、标注、选字三种状态设计稿：明显而舒展的圆润感、浅绿主题、较深绿色默认标注，统一工具栏和选字反馈。审美作为产品核心；截图后自动本地识字，用户主动复制，识别不阻塞截图且不自动覆盖剪贴板。AI 暂缓。普通截图保留原图四角，界面圆角不等于导出裁圆角。

[本轮设计候选](ui-v4/README.md)仅用于审美与交互评审。具体圆角、色值和布局未获最终视觉确认，未修改原生应用。

### 2026-11-08 · 完成出口与固定审美（用户已确认）

主按钮统一为“完成”：有选中文字就复制文字，否则复制图片，成功后结束截图；⌘C 使用同一目标规则但不结束。保存输出图片文件，钉住转为桌面浮窗。选字不再弹出复制/全选小面板，两项操作保留在右键菜单；快捷键放到悬停提示，去掉底部常驻说明。

### 2026-11-08 · 保存位置自由选择
