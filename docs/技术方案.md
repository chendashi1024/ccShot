# CcShot 技术方案与 S0 核验

日期：2026-11-03。状态：**方案草案，未确认、未进入正式 App 开发**。本文件给出本地优先路线及官方资料，不将建议、接口可用性或既有原型的局部结果写成产品验收通过。范围、交互与未决事项分别以 [GOALS](../GOALS.md)、[功能清单](功能清单与验收标准.md) 和其中的 D01–D12 为准；任务和原编号对应见 [开发阶段与任务拆解](开发阶段与任务拆解.md)。旧 PRD 与历史决定保留。

## 一、结论和选择

- 建议从 **macOS 14、Apple Silicon** 开始做验证基线，是否支持 Intel 和 macOS 13 仍由 D01 决定；不把建议当作已承诺的兼容范围。14 提供单帧截图接口；13 可探索采集流取首帧，但需要额外处理启动、停止、权限和帧到达，并在 13 实测；原型使用的部分选字 API 也要求 14。跨屏和选字缺口不能由升级基线自动解决。
- Swift + AppKit 负责遮罩、选区、画布和钉图，SwiftUI 用于设置和面板；Apple ScreenCaptureKit 捕获、VisionKit 优先做本地可选文字。现有[原型报告](../prototype/local-ocr/TEST-REPORT.md)显示受控窗口单个鼠标选字用例可行；程序化四字多选一字、真实全局热键和混合多屏仍未通过或未测。原生方案不达精确选择要求时，再评估 Apple Vision 识别结果加自有文字选择层；成本是自行处理阅读顺序、字符范围、文本布局、可访问性及多语言，不能退化成只能全文复制。
- 原有 44 项 MVP 不缩减，先本地体验，S5 才接用户自配 Key 的云 AI；DeepSeek 已暂停，不把旧预设或默认值当作当前决定。S6 的更新、安装、权限与发布均未验证。

## 二、关键 API 的范围

以下是公开资料与本机 macOS 15.4 SDK 头文件的可用性核验；不等于本产品在这些系统或架构实测通过。不同 API 成员可能有各自的最低版本。

| 能力 | 基线/事实 | 对方案的影响 |
|---|---|---|
| `SCShareableContent`、`SCContentFilter`、`SCStream` 基本截屏流 | 本机 SDK 头文件标注 macOS 12.3；[Apple 采集示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) 展示过滤内容和流式接收帧，示例当前要求 macOS 15 不代表框架最低版本 | 13 可设计首帧流方案，需另测权限、首次帧、取消与资源释放。 |
| `SCScreenshotManager.captureImage(contentFilter:configuration:)` | 本机 SDK 标注 macOS 14 | 14 候选基线可用单帧路径；图像尺寸、色彩与内容过滤仍须测。 |
| `SCScreenshotManager.captureImage(in:)` | 本机 SDK 标注 macOS 15.2 | 不能作为 macOS 14 跨屏基础实现。 |
| `ImageAnalyzer` / `ImageAnalysisOverlayView` | [Apple WWDC22](https://developer.apple.com/videos/play/wwdc2022/10026/) 说明 macOS 13 的 Live Text 交互；[Apple 叠层说明](https://developer.apple.com/documentation/visionkit/enabling-live-text-interactions-with-images) | 将叠层绑定到图像实际显示区域，通过交互代理做命中仲裁；识别质量和准确选区必须实测。 |
| `ImageAnalysisOverlayView.text`、`selectedText`、`selectedRanges`、`textSelectionDidChange` | 本机 macOS 15.4 SDK 的 VisionKit Swift 接口对这些成员分别标注 macOS 14；其所属叠层类型标注 macOS 13 | 不能把 13 有 Live Text 视为原型代码可直接在 13 使用；若支持 13，读取所选文本、范围和选择变化的替代路径需单独设计及实测。 |
| 权限 | [Apple 屏幕采集示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) 指出首次需屏幕录制授权，示例获授权后需重启 | 申请前说明用途；拒绝、撤回、更新后的恢复路径分别实测，不能假设所有系统行为相同。 |

## 三、模块和数据流

| 模块 | 建议职责 | 出错处理 |
|---|---|---|
| 菜单栏、快捷键 | 管理应用生命周期、F1/F3、可改快捷键与冲突反馈 | 注册或回调失败时菜单仍可进入；退出清理热键和浮窗。 |
| 截图和选区 | 按显示器身份取得快照；区域、窗口、当前屏选择，调整控制点、放大镜和取色 | 权限拒绝、显示器拔出、目标窗口消失、零尺寸与取消不得返回旧图或假成功。 |
| 会话与坐标 | 每张图独立保存原始像素、显示器信息、选区、对象、当前修订号 | 屏幕变化取消或可恢复；不串会话。 |
| 本地文字 | VisionKit 异步识别并叠加选择；截图和钉图共用图像坐标 | 无字、失败、迟到均不阻塞图像输出；文字不可用时不返回旧结果。 |
| 标注 | 九工具、可编辑对象、样式和撤销重做；仅选择态允许文字命中 | 未提交手势可取消；输入法、工具、文字层各自有优先级。 |
| 合成和美化 | 基于当前裁剪与已提交对象生成单一输出；背景、比例、圆角、阴影、内边距 | 复制、保存、钉图共享同一结果；渲染失败保留会话。 |
| 钉图 | 独立窗口保持源图与当前会话，可缩放、透明度、继续选字和标注 | 缩放仅改变预览，不降低导出源像素；关一张不污染其他图。 |
| 设置、权限 | SwiftUI 设置、系统权限检测、目录及开机启动等 | 权限或偏好失败明确提示；不伪报生效。 |
| AI（S5） | 用户主动选厂商、端点和模型；钥匙串保存 Key，直连服务并流式显示 | 未配置不影响本地功能；取消和迟到结果可丢弃，绝不记载密钥或原始用户内容。 |
| 更新和打包（S6） | 根据 D02、D07、D09 确认后实现 | 校验失败/更新失败保留可运行版本；发布与本地打包分开。 |

数据流建议：截图快照 → 原像素与选区 → 非破坏式标注 → 当前安全合成 → 复制/保存/钉图或用户主动发送 AI。OCR 和 AI 任务绑定会话、图像修订、请求身份；裁剪、遮挡、换图或关闭后旧结果失效。被遮挡或裁掉的原始 OCR 不得走复制全部、附带文本、元数据等旁路；安全文本未就绪则阻止文字输出并提示，不能退回旧缓存。马赛克与模糊不承诺不可逆脱敏，完全遮盖需实心覆盖。部分遮挡时，若识别单元与遮挡或裁剪边界相交而无法证明未被遮挡的文字边界，先屏蔽该整个单元及已有选择，或对安全合成图重新识别并继续过滤；不得将旧整行文字输出。遮挡的移动、缩放、透明度变化、删除、撤销/重做和底图改变也使相关结果失效。可见手势尚未提交时，应先安全提交/取消或暂停相关输出，不能发送屏幕看起来已遮挡、实际仍未遮挡的旧内容。每次 AI 发送及能力降级重试前再核对会话与图像修订，丢弃不匹配的已序列化载荷；已发送给服务商的数据无法撤回。复制与保存的各图像表示、缩略图和元数据也必须来自当前安全合成结果，不附可恢复原图或隐藏图层。

## 四、坐标和交互草案

### 坐标

1. 以每个显示器的实际身份、屏幕坐标、采集图像像素宽高和颜色信息记录截图，不假定所有屏同一比例或原点为正。
2. 视图交互用点（pt），图像裁剪及方向键 1 px、Shift + 方向键 10 px 微调用图像像素（px）；通过当前显示器和图像的实际变换来换算。每次换屏、窗口缩放及显示布局变化重新计算；矩形取整规则应保持包含关系并用像素标尺验证。不得直接对所有屏套一个 `backingScaleFactor`。[Apple 高分辨率指南](https://developer.apple.com/library/archive/documentation/GraphicsAnimation/Conceptual/HighResolutionOSX/APIs/APIs.html) 建议使用屏幕/窗口坐标转换与像素边界对齐。
3. 建议先保证每屏内单一区域精确，跨两屏同一选区按 D08 决定：如支持，按显示器分片获取并定义混合缩放、拼接密度、接缝及颜色空间；不能用 15.2 新接口假装覆盖 14。负坐标、不同缩放、屏幕上下排列、跨屏窗口及拔插均待真机验证。
4. 取色基于实际合成前图像像素；色彩空间和数值转换须固定并用已知色块验收，不能把显示器颜色与输出数值简单视为同一结果。

### 单屏坐标换算候选（用于 D08 评审）

AppKit 的全局屏幕坐标通常以主屏左下为原点、Y 向上；Quartz 的全局显示坐标以主屏左上为原点、Y 向下。二者不能把同一个数值直接互当坐标；窗口和视图应使用系统提供的转换方法。`NSScreen.mainScreen` 是当前键盘焦点所在的屏幕，不应当作固定主屏。显示器连接、拔出或排列变化后须重新建立映射。来源：[Apple 坐标系](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CocoaDrawingGuide/Transforms/Transforms.html)、[CGDisplayBounds](https://developer.apple.com/documentation/coregraphics/cgdisplaybounds(_:))、[NSScreen.screens](https://developer.apple.com/documentation/appkit/nsscreen/screens)。

下面仅是可验算的**假设示例**，不是跨屏或旋转屏的已测实现：某个未旋转屏幕的 AppKit frame 为 `(sx, sy, W, H)`，整屏快照恰好对应其完整区域、大小为 `P × Q` 像素。先用系统转换得到以该屏左下为原点的选框边界 `x0, x1, y0, y1`。如果选择外扩到覆盖触及的像素，图像左上原点的像素边界候选为 `left=floor(x0×P/W)`、`right=ceil(x1×P/W)`、`top=floor((H−y1)×Q/H)`、`bottom=ceil((H−y0)×Q/H)`，再裁入图像边界，宽高分别为 `right−left` 和 `bottom−top`。反向拖动先规范最小和最大边界；零面积不输出。

- 假设主屏 `(0, 0, 1440, 900)` pt、快照 `2880 × 1800` px，屏内框 `(10, 20, 100, 50)` pt，候选像素框为 `(20, 1660, 200, 100)` px。
- 假设左屏 `(-1280, 0, 1280, 720)` pt、快照 `1280 × 720` px，全局框 `(-1270, 20, 100, 50)` pt，转换到屏内后候选像素框为 `(10, 650, 100, 50)` px。

外扩可能带入选框边缘以外的像素，尤其影响隐私；如果采用它，用户看到的边框必须对齐最终输出像素，不能悄悄包含不可见内容。是否外扩、单选区跨屏后的输出密度、接缝及色彩仍由 D08 决定。旋转、镜像、非整数缩放、跨屏窗口和热插拔都需要实测，上式不能直接作为这些场景的结果。

### 输入

输入优先级、Esc、⌘C、双击、滚轮和中文输入法以[交互合同](功能清单与验收标准.md#interaction)为草案：系统弹窗/输入法候选优先，其次文字控件、当前手势和面板、画布工具、截图会话、全局快捷键。选择态文字拖选；绘制态画笔独占；已有对象控制点优先。OCR 结果到达时不抢焦点。钉图查看态滚轮缩放，编辑态滚轮只调整对应工具；透明度建议只改变查看效果。四个画面见 [界面草案](界面草案.html)，仅供评审，不是原生应用实测。

## 五、快捷键

[KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts) 是可自定义全局快捷键的 MIT 开源候选，支持 SwiftUI 记录器；其说明称不支持媒体键。F1 默认可能控制亮度，Apple 说明可配合 Fn/地球键或设置标准功能键：[Apple 支持](https://support.apple.com/en-us/102439)。原型中 F1、Control+Option+S 注册返回成功但回调未记录：建议将后者作为**待测备选**，并允许自定义，不能保证它在用户设备或其他应用不冲突。用真实键盘、其他应用前台、睡眠恢复、两种功能键设置与冲突案例测回调，保留菜单栏入口。

## 七、分发、更新和许可

- 已有方向是不购买开发者账号、不做 Developer ID 签名公证，使用 ad-hoc 签名和 GitHub Releases。基础签名命令示意 `codesign --force --sign - CcShot.app`；含嵌套框架时须按依赖从内到外签名并验证，不能把一条命令视为完整发行脚本。ZIP 可用 `ditto -c -k --sequesterRsrc --keepParent CcShot.app CcShot.zip`，DMG 可用 `hdiutil create` 制作后在干净机器核验挂载/安装；[Sparkle 打包文档](https://sparkle-project.org/documentation/publishing/)特别强调保留软链接。命令均为设计示例，尚未对产品包执行。
- [Apple 未公证应用的打开说明](https://support.apple.com/en-us/102445/)提供系统设置中“仍要打开”的路径，实际界面随系统版本核对。`xattr -dr com.apple.quarantine` 会移除指定路径的隔离属性，不能当作签名或真实性验证；如提供手动路径，必须先核对来源和校验值、仅对明确下载的应用执行，不要求关闭 Gatekeeper。升级与屏幕录制权限是否保留需在目标机器实测。
- [GitHub Actions 中使用 GitHub CLI](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-github-cli) 可用于自动化；构建、写入权限和发布工作流尚未搭建。Homebrew [官方 cask 规则](https://docs.brew.sh/Acceptable-Casks)要求受 Gatekeeper 检查的产物通过检查；[自建 tap](https://docs.brew.sh/How-to-Create-and-Maintain-a-Tap) 可维护自有 cask，但不保证绕过系统安全检查。历史材料中的具体生效日期此处未核实。
- [Sparkle 文档](https://sparkle-project.org/documentation/)要求保护更新签名私钥并建议 HTTPS；更新包采用 EdDSA 校验，Developer ID 与其作用不同。当前 ad-hoc 框架嵌入、安装、更新替换、隔离和权限恢复未实测，因此不能保证无 Developer ID 可正常更新；失去更新私钥后的恢复条件也须单独设计。#56 未经用户批准不得静默延期，D02/D09 未定。
- [MIT 许可证](https://opensource.org/license/mit)是适合考虑的宽松候选，须保留版权和许可文本，D07 未定。参考代码要按**具体仓库和文件**核许可证：例如 [sw33tLie/macshot](https://github.com/sw33tLie/macshot) 为 GPL，不能把其代码直接混入仅 MIT 发布的项目；[Snapzy](https://github.com/duongductrong/Snapzy) 为 BSD-3-Clause，[capcap](https://github.com/realskyrin/capcap) 为 MIT，取用时仍须核对版本和依赖并保留所需声明。不要混淆同名项目。

## 八、下一步与未决项
